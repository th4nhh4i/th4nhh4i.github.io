Can You Remember 1 & Can You Remember 2 — 5 000 pts each

The year is 2077. Thanks to advances in technology, you can now fight malware in first person.

Each mission drops you into a network of hosts. You know how many hosts it holds, but not what waits on them. A host may carry a malware sample, or it may be clean. To clear an infected host, name the malware family so the system can apply the right cure. Your entry host is always safe.

Once a host is clear, step through one of its five warps to a neighbor and keep mapping the network. When you finish exploring, a short sanity-check quiz confirms what you learned. Pass it, and the reward is yours.

⚠ Live malware. The sample zips hold live malware. Handle them only in an isolated VM or sandbox. Every zip is locked with the password infected.

Network

  • Hosts: 20
  • Warps per host: 5, numbered 1..5

Hosts and identity

Each host holds a malware sample or is safe. GET /host/current gives a link to a password-locked zip in sample_url. Download it, analyze the sample, and name its family. A safe host has no sample: sample_url is null, solved is already true, and you classify nothing to move on. The start host is always safe.

The link is valid only while you stand on the host. Each arrival mints a new sample_url for the same sample, and the earlier link stops working. A revisit therefore needs a new correct classify: leaving a host clears its solved state.

Movement

You must classify a host correctly before you can move from it, every time you stand on it. A safe host is the exception: it holds no sample, so you can move on at once. You have 3 hearts. A wrong guess spends 1 heart; at 0 hearts the instance ends. POST /move walks a warp to the neighbor host and spends 1 of 1 000 moves. POST /reset returns you to the start host and is free.

Warps are two-way. If a warp leads from a host to a neighbor, exactly one warp on that neighbor leads back. That return warp usually has a different number. Example: you leave a host through warp 3 and arrive at a neighbor. From that neighbor, warp 1 — not warp 3 — takes you back.

Instance

An instance lives for 1 hour. The server blocks and deletes it after that, so finish the sanity check before the hour runs out.

Sanity check

POST /sanity-check/questions returns 100 questions about the network. Each question states its own task in words. Each question carries an id. POST /sanity-check/submit sends one object that maps each id to your answer. Use "safe" for a safe host. Exploration stops the moment the sanity check starts, so you cannot walk a route after you read it.

  • Flag 1: Awarded when at least 50% of the quiz answers are correct.
  • Flag 2: Awarded when at least 99% of the quiz answers are correct.

Auth

Call POST /instance/start first. Send the returned instance_id in the X-Instance-Id header on every other request.

1.3. Định danh sample khi server chống hash lookup

GET /host/current trả sample_url → zip khoá password infected, bên trong là sample.bin.

Quan sát:

  • Mỗi lần đến host, server mint URL mới → hash zip đổi.
  • Đổi instance → nội dung sample.bin cũng đổi hash.

⇒ Không tra được VirusTotal/MalwareBazaar bằng hash. Đây là chống-cheat có chủ đích.

Ba dạng biến đổi được áp lên cùng một sample gốc:

  1. Append zip "mitra" ~192 byte ở cuối (chứa mitra_stub.txt = mitra-payload) — polyglot decoy, khiến file báo nhầm "Zip archive, with extra data prepended".
  2. UPX-pack (có bản packed, có bản không).
  3. Zero-hoá TimeDateStamp trong PE header (vài sample mutate thêm vài chục byte).

Giải pháp: normalize + fuzzy clustering

def norm(d):                      # bins/*.bin -> norm/*.bin
    return upx_unpack(strip_mitra_overlay(d))

def blocks(d, B=512):             # fingerprint = tập hash của block 512 byte
    return {sha1(d[i:i+B])[:8] for i in range(0, len(d), B)}

sim = jaccard(blocks(a), blocks(b))     # cùng family ⇒ > 0.9

Union-find gom cụm ở ngưỡng 0.80.

1.5. Dựng lại đồ thị khi các host không có định danh

/host/current không trả host id, và nhiều host mang cùng family (trong một instance mẫu: shamoon ×6, trickbot ×5, njrat ×4, safe ×4) ⇒ family một mình không định danh được đỉnh.

Định danh bằng chữ ký cục bộ

sig(node) = ( family(node), (family(nb₁), …, family(nb₅)) )

Hai path cho cùng sig ⇒ coi là cùng một đỉnh.

Điểm tinh tế: nếu hai đỉnh thật sự không phân biệt được ở mọi độ sâu thì chúng liên hệ qua một automorphism giữ nhãn port ⇒ mọi route từ entry vẫn cho cùng chuỗi family. Ta chỉ cần quotient automaton, không cần đồ thị thật. (Trong lần chạy thực tế, 20 host quy về 19–20 lớp tương đương.)

Chi phí và tối ưu

  • goto(p) = /reset (free) + đi lại từ đầu ⇒ probe 1 warp của path p tốn len(p)+1 move.
  • Probe đủ 5 warp của một đỉnh depth-2 = 15 move.
  • BFS ngây thơ: mỗi đỉnh mới sinh 5 path con ⇒ ~100 probe ⇒ ~1500 move → vỡ ngân sách.

Ba tối ưu:

  1. Cache family theo path — chỉ tải sample ở path chưa gặp (WannaCry nặng 3.4 MB, tải lại mỗi lần sẽ rất chậm).
  2. Adaptive probe — probe từng warp một, dừng ngay khi chỉ còn đúng một đỉnh đã biết khớp prefix. Path trùng ở depth-3 giảm từ 20 → 12 move.
  3. Suy ra cạnh miễn phí — khi probe đỉnh n ta đã biết family của cả 5 con. Nếu family đó chỉ thuộc về đúng một đỉnh đã biết ⇒ cạnh xác định, 0 move. Chỉ cạnh mập mờ mới cần ghé thăm.
def identify(p, full=False):
    f = famof(p)                       # thường đã có sẵn trong cache
    cands = [nodes có cùng family]
    for w in 1..5:
        if not full and len(cands)==1 and w>3: break      # đủ để phân biệt
        goto(p); step(w); ch[w] = look()
        cands = [n for n in cands if n.ch[:w]==ch[:w]]
        if not cands: full = True      # đỉnh mới -> cần chữ ký đầy đủ
    return cands[0] if len(cands)==1 else new_node(f, ch)

Kiểm chứng trước khi nộp

3. Logic từ Flag 1 đến Flag 2

3.1 Bổ sung fingerprint cho sample UPX mới

Trong các instance mới xuất hiện biến thể có SHA-256:

cd4030b5de1fa7581ef6d3c20919f244f6d6c5d12edf6f6aa6e5d447544e5dca

Sau khi giải nén UPX, fingerprint khớp với cụm Hive chuẩn 42101d4790538fb8df92802bbc79b0a1c331043db7843ef86cdd7ae0e4501a12. Ánh xạ này đã được thêm vào canon.json. ident.py cũng được sửa để tự tìm UPX 4.2.4 ở ../upx_dist/... hoặc ./upx_dist/... khi upx chưa có trong PATH.

3.2 Vì sao mô hình 94% chưa thể đạt 99%

Chữ ký một bước (family(node), family(neighbor_1)..family(neighbor_5)) đủ để tách 20 trạng thái trong lần chạy tốt nhất, nhưng chưa xác định duy nhất cách ghép 100 port thành 50 cạnh. Nhiều đồ thị 5-regular khác nhau vẫn thỏa cùng bảng family lân cận và cho dự đoán khác nhau trên các route dài.

Sai số lớn nhất đến từ việc coi mọi mục path2n hoặc nb là cạnh chắc chắn. Một path có thể bị gán nhầm sau khi mới probe 2–3 child family; chỉ vài cạnh sai là đủ làm lệch nhiều câu hỏi phía sau.

3.3 Sửa lỗi transition prefix

Trong bản cũ, một path dài đôi khi được dùng như bằng chứng cho nhiều transition trung gian nhưng đích lại bị gán về state của toàn bộ path. Bản cuối chỉ chấp nhận transition giữa hai prefix liên tiếp đã được nhận diện:

for path in identified_paths:
